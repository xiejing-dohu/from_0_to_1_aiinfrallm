## 为什么五个工具就够了

一个更大的工具目录并不能自动提高能力. 每一个计划消耗
上下文,并给予模型另一种选择。 五个工具涵盖基本
软件开发周期:

- `list_files` 进行有界限的目录发现;
- `read_file` 收集一个带边框的 UTF-8 文件;
- `edit_file` 进行目标明确、可审查的替换;
- `write_file` 创建文件或有意替换其内容;
- `run_command` 运行一个精确的运算符分配参数向量。

这个模型可以使用 `rg`, `find`,或仅在操作员有
允许该精确参数向量用于 `run_command`。稍后可以添加
评估表明重复的工作流程不可靠时的专门工具,
不仅仅是因为另一个命令的存在。

## 列表文件

路径是可选的, 默认为工作空间根 :

```json
{"tool":"list_files","path":"src"}
```

结果确定条目为文件或目录,省略受保护路径,
连锁,并在保险单的进入限制后停止。

## 读取文件

当前接口读取一个完整的边框文件 :

```json
{"tool":"read_file","path":"src/parser.py"}
```

应用字节限制, 因此一个缩写或二进制文件不能淹没上下文 。
拒绝目录,超大小文件,以及有明显错误的非UTF-8文件.
线条窗口是可能的扩展, 但是 `offset` 和 `limit` 没有字段
目前的行动计划。

## 编辑文件

使用精确的文本替换而不是要求模型重写整个
文件 :

```json
{
  "tool":"edit_file",
  "path":"src/parser.py",
  "old":"if not value:\n    return None",
  "new":"if value is None:\n    return None"
}
```

旧文本必须完全匹配一次。 零匹配通常意味着模型需要
重读文件。 多重匹配意味着它必须选择一个更具体的区域.
当前基线返回已改变的路径; 添加一个已绑定的统一 diff
追踪是计划进行的可审查性改进。

精确编辑有有用的失败语义: 当文件没有时它拒绝应用
与模型所观察到的相对应。

`edit_file` 只有在操作员允许写入时才可用。 连
然后,每个模式分发的动作通过 `Workspace.execute()` 必须通过它
在它停下来问起之前 `y/N`。只有明确肯定
后批准重新检查和原子编辑。 直接的方法呼叫是信任的,
用于聚焦工具测试的无模型层,而不提示。

## 写入文件

`write_file` 用于创建新文件,但覆盖已有文件
是一个比精确编辑更大的突变。 首先必须读取已有文件 。
执行内容限制并使用原子替换,这样中断不会离开
a 部分书面文件。 喜欢 `edit_file`,每个合格的模型分发
飞行前通过的行动需要明确 `y`/`yes`; 显示
默认为 No.

## 运行命令

输入是一个非空JSON阵列. 它必须完全等于一个引力
提供操作员 `--allow-command`:

```json
{"tool":"run_command","argv":["pdm","run","test","--week","1","--day","3"]}
```

按执行顺序抓取stdout和stderr,包括退出代码,
并盖住返回模型的东西。 目前的基线保留了界限
前缀并附加一个折射标记; 它不保存一个完整的临时标记
日志。

超时属于 `ToolPolicy`而不是示范行动。 它试图
终止命令的相同进程组后裔并获取前景
孩子们 一个子孙创造了另一个会话 能够逃脱这种清理,所以
仍然需要一次性工作空间和加强操作系统流程隔离
敌对命令。 第2天的检查站,跑步手把柄
`KeyboardInterrupt` 当命令生效时。 累积参考
在整个循环中增加了一个合作取消信号,
课程模型解码器, 指挥投票, 和方向在第6天;
不是第2天的重点检查

明确允许列名是必要的,但还不够。 每个符合条件的
模式分发 `run_command` 飞行前通过的行动 `y/N` 和
默认为 No 。 跑者不援引外壳,但允许的可执行文件
本身删除文件、在工作空间外读取、产卵儿童或使用
腾讯网.

> 运行中的命令 `cwd` 设置为寄存器仍然可以在外部读取文件
> 该目录。 仅在一次性工作空间运行此课程代理 。 路径
> 验证是有用的,但它不是进程隔离的替代.

## 可执行的Schema

当前解析器将所需和可选字段作为数据:

```python
TOOL_FIELDS = {
    "list_files": (frozenset(), frozenset({"path"})),
    "read_file": (frozenset({"path"}), frozenset()),
    "write_file": (frozenset({"path", "content"}), frozenset()),
    "edit_file": (frozenset({"path", "old", "new"}), frozenset()),
    "run_command": (frozenset({"argv"}), frozenset()),
}
```

保持及时、解析、可用性政策、核准政策和发送名称
双方同意 未知、残疾、畸形或被人类否认的行为
可回收的观察而非操作系统调用.

## 当前检查站

执行 `parse_action()` 和 `build_system_prompt()` 输入
`src/tiny_llm/agent/protocol.py`,然后运行 :


## 累积工具练习

使用这五个工具,并在以后没有模型的情况下对其进行测试
检查站:

1. 列出一个有界限的目录并读取一个有界限的UTF-8文件.
2. 拒绝零匹配或多重匹配的编辑。
3. 在保存文件的行尾时应用唯一经核准的编辑.
4. 创建一个经核准的文件,并否决所配置的限制内容。
5. 拒绝批准时的变异和命令;
6. 运行一个精确的核准命令,成功,失败,以及
   时间流逝。
7. 在保留其退出状态的同时,限制大量命令结果。

然后给特工一个包含一行错误的固定寄存器. 一个成功的
轨迹应检查执行情况并测试,精确编辑、运行
重点测试,并返回一个最后的答案。 这个模型支持的轨迹是
课程目标;当前第2天的测试具有决定性,不装入模型。
