# 🚧 第 2 周：向 vLLM 更进一步

> **现状:实验。** 第2周正在积极发展之中。 每一章
> 载有自己的核查说明;下文摘要记录的是
> 不断测试单机研究证据。

第2周维持第1周 Python `mlx.core` 模型完好无损,另建一个
优化 Qwen3 用于单一请求解码的路径。 从算法开始
更改: prefill 一次,保持密集 KV cache,以及 decode 一个新的 token 以美元计
时间 后几章介绍内核处理成本 KV cache
揭发。

> ⏱️ **时间承诺。** 第3-7天 写作和曲调习惯 Metal 内核.
> 完成整个第2周的序列通常需要比
> 第1周 第6-7天。 所有七天都是核心材料;计划是相应的。

第2周保留 BF16 以重、量、偏、
激活,预测,KV-cache条目,以及模型化内核输出.
包装的W4重量代码为 `uint32`微量敏感减少,
点产品和在线软件状态在 FP32 内部 Python
参考表达式或内核登记册。 本合同对
第3个星期。

在一个M4 Pro上测量的研究数据,而不是交叉设备的保证. 原始内容
测量、拒绝的实验和保留的调度选择

## 我们的掩护

- 用于增量解码的密钥值缓存
- 同步基准和密集度 decode 屋顶线
- 包装W4量化和a SIMD 矩阵显示器 Metal 内核
- 废了 RMSNorm, RoPE,和斯维格卢 Metal 内核
- 在线软件解码器内核
- A BF16 SIMD 矩阵定量 prefill 内核
- 小型的形状感知分型K时间表 Qwen prefill 矩阵
- 用于生成的最后一个输入式输出接口
- 80%的可选伸展目标 MLX prefill 和 decode 吞吐量
  第2周固定检查站

第二个星期 **没有** 调用 MLX 提供的操作器执行
学习。 您的解决方案已定量 matmul, decode 请注意, RMSNorm,
RoPE,和SwiGLU在自己的 Python, C++,或 Metal 代码。 特别是,
已完成的检查站不使用 `mx.quantized_matmul`, `mx.dequantize`,
`mx.fast` 运算符,或 `mx.fast.scaled_dot_product_attention` 作为快捷键。
第1天的基线仍然使用第1周 Python `mx.dequantize` 装入辅助器;
第3天取代了装填路径 作为保持重量包装的一部分.

第2周用途 `mlx_lm` 装入模型重量和 `mlx.core` 对于数组, 图表
评估,以及设备同步。

## 每周检查点

1. **KV cache:** 将“周1”操作符移植到“周2”模型中,添加
   请求范围状态,并停止重算前缀。
2. **基准和概况:** 以 MLX 带有
   匹配,同步协议。 剖析是可选的,并推迟到
   macOS 27 工具可用.
3. **量化型号:** 保留 W4 权重包装, 执行矩阵显示器
   Metal 并重新运行第2天的基准。
4. **引信型号内核 :** 引信 RMSNorm, RoPE,而 SwiGLU 一个操作员在一个
   组合预测后的时间缩小了基准差距。
5. **Decode 注意:** 介绍 online softmax 超过测试
   短文本范围,并用相应的工作量加以核实。
6. **SIMD 矩阵 prefill:** 恢复固定的128个工作负担并替换
   使用合作牌的正确性第一矩阵路径。
7. **分割 K prefill:** 分区 仅针对填充不足的缩小尺寸
   短的预测,然后回到第6天 测量交叉。

## 第2个星期至第3个星期

完成的第二周模型解码 token 一次从密集的 KV cache,
单独发送 prefill 和 decode 矩阵时间表,并保持加权数
整个被量化。 第1周继续使用 Python `mlx.core` 完整前缀
生成循环。

第3周导入这些第2周接口,而不是复制或替换.
它增加了页表翻译 结合了第二周 online softmax,
SIMD- matrix 板块, 页面行走在一个页面中 FlashAttention 操作员。 那个
边界让每周的模型保持可理解性,可以自行运行.

运行 `pdm run bench-week2-progression` 以衡量每个检查站对
第1周基线和 MLX. 全面方法和累积结果
[业绩附录](./appendix-performance.md)。默认值运行引用
检查站; 添加 `--solution tiny_llm` 以衡量您的执行。
