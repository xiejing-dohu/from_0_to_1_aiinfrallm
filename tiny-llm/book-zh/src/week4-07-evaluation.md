## 检查章节

实施评价 `src/tiny_llm/agent/`,然后运行 :

```bash
pdm run test --week 4 --day 7
```

使用 `pdm run test-refsol --week 4 --day 7` 用于提供的执行。 那个
焦点套件使用脚本模型动作和惰性固定装置. 三角线验证
分级不会启动进程、导入候选模块或调用
`eval()` 或 `exec()`.

您可以检查和分级一个不变的任务固定,而不装入一个模型:

```bash
pdm run evaluate-agent inspect evals/week4/localized-constant
pdm run evaluate-agent grade evals/week4/localized-constant
```

第二个命令是固定到一个新的临时目录,冻结
并且只进行申报性暂停检查 它没有运行
编码代理或批准一种变异。 使用 Python API 以评价脚本
或模型支持的轨迹。 `inspect` 有效软件包退出零; `grade`
退出 0 表示通过, 1 表示决定失败, 2 表示无效
软件包或 CLI 错误。 发运的未变的局部稳定基线是
故意错误, 因此它会返回一个正常的失败报告 。

## 密封的惰性任务包

每个任务都有一个目录,其中包含一个公开清单、一个起始工作空间和一个
hold- out 声明性检查文件 :

```text
localized-constant/
  task.json
  workspace/
    answer.py
  held_out_tests/
    checks.json
```

`task.json` 严格且版本化:

```json
{
  "schema_version": 1,
  "id": "localized-constant",
  "prompt": "Correct the answer without changing the public name.",
  "max_steps": 6,
  "editable_paths": ["answer.py"]
}
```

装载器拒绝缺失和未知的字段, 不支持的计划版本,
空白的标识符或提示,无效的预算,绝对路径,父路径,
重复可编辑路径,重复可编辑路径前缀。 还有
拒绝共鸣, `.git`,过多的文件计数或字节,未知的软件包
条目,以及可执行保存的文件。 软件包不能包含 `grade.py`, a
命令,或另一个任务本地程序。

`TaskPackage.stage()` 仅复制 `workspace/` 进入一个新的狭窄的目的地。
目的地不得含有候选树. 暂停检查,
解析历史,并且软件包元数据从不进入代理可见的工作空间。
显示每个初始正则文件的排序快照和条条
树种 SHA-256,它也涵盖目录的存在,而不修改原始
软件包。

这些规则使包括的固定装置变得惰性和可复制。 他们不是
使无信任的仓库安全的一般方法。 解析一个软件包仍读
由作者提供的字节,而后面的代理运行只能像
其启用的工具。

## 保留禁用的命令并写入默认 - 否

`evaluate_task()` 创建一个 `Workspace` 其命令许可列表为空 。 一个
请求代理行动 `run_command` 在进程启动前被拒绝。 那个
使用评价不会将显示的数据转换成参数,也不会
提供任务本地验证命令。

文件写作仍受正常工作空间检查和每名呼叫人员检查
确认召回。 如果不提供回调, 则拒绝写入 。 那个
评测员从不代表被调用者安装一贯是的回调. CLI或
应用程序想要模型授权的变异必须给出精确的工具调用
执行同样的明确 `y/N` 政策作为主要代理人CLI:空白输入,
EOF, 非交互输入, 中断, 以及除 `y` 或 `yes`
没有

这使得评估人员具有小的能力界限:

```text
public manifest + staged workspace
                |
                v
       bounded agent loop
       writes: explicit y/N
       commands: disabled
                |
                v
       frozen candidate tree
                |
                v
     static held-out grader
```

它不能使主机执行安全。 不启用 `run_command` 任务
更现实:核准 Python 程序或测试可以在
工作空间,读取证书,访问网络,或者创建脱离进程.

## 在显示已挂起的检查前冻结

评价的生命周期是命令的,因此隐藏的预期不能影响
代理轨迹 :

1. 验证软件包并仅设置其公共工作空间。
2. 记录初始文件快照和树散列。
3. 以禁用的命令运行边框代理,并将默认写入 No.
4. 在有效最后行动、预算终止、中断或其他行动之后停止
   记录的终端原因。
5. 将候选人复制成一个单独的、只读在业者评分快照。
6. 记录 `evaluation_started` 带有任务ID和候选树散列。
7. 装入 `held_out_tests/checks.json` 这是第一次
8. 对冻结的快照进行允许列入清单的静态检查。
9. 记录 `evaluation_result` 与等级,命令检查结果,禁止
   修改和衡量标准。

分级者从未观察到一个活树,即代理可以继续改变的树.
这个检查站将一个阶段性任务及其会话作为单一用途处理。 坠机
之后 `evaluation_started` 但在此之前 `evaluation_result` 留下一个不完整
记录; 重修和重修任务,而不是默默地分级不同的字节。
隐藏的预期值不包含在模式消息或预级会话中
事件。

冻结会缩小评价者一致性差距,而不是每个主机比赛. 一个单独的
同一用户进程在复制普通文件时仍可干扰普通文件.
当任务输入或相邻进程时使用容器或虚拟机
无信.

## 声明挂载- 退出检查

`StaticHeldOutGrader` 接受只包含小
允许检查列表 :

- `path_exists` 需要相对路径的正则文件;
- `path_absent` 要求不存在相对路径;
- `text_equals` 比较受约束的UTF-8内容;
- `json_value` 剖析 JSON 并在已声明路径中比较一个值;
- `python_constant` 剖析 Python 与 `ast.parse()` 检查一个字
  任务;
- `unchanged` 比较路径及其初始快照。

每次检查都有严格的字段和限定输入. 不支持或变形
检查产生评价错误,绝不是假通行证。 成果和途径
排序了相同的清单,检查规格,以及候选字节
同样的 `GradeReport`.

那个 Python 检查是语法检查,而不是程序执行. 它不导入
候选人,将已设置的目录添加到 `sys.path`,评价一个表达式,
执行模块,或启动程序。 文档可能包含危险外观
高层电话; `ast.parse()` 作为节点代表它们,不运行它们。
检查只接受支持的字面指派形状并拒绝其他
表达法。

在申报检查后,分级员将冻树与初始的
即兴表演。 创建、修改或删除外部路径 `editable_paths` 是一个
禁止修改,即使每次暂停检查都通过,也未能达到等级要求。
候选人的树丛和命令的禁路名单作出这一决定
可审计。

静态检查有意涵盖的行为比可执行测试少. 他们是
适合本地化常数、准确文本、寄存器配置、文件
存在,以及小的语法形状练习。 他们不能证明是任意的
Python 代码行为正确。

## 补全不正确

循环和分级回答不同的问题:

| 信号 | 含义 |
| --- | --- |
| `AgentRun.completed` | 模型返回一个有效的最终动作 |
| `AgentRun.reason` | 为何终止限定的代理循环 |
| `GradeReport.status` | 确定性检查是否通过、失败或错误 |
| `EvaluatedRun.task_success` | 是否为 `GradeReport.status == "passed"` |

与错误字节对齐的流畅最终消息完成但失败 。 一个跑步
当它最后冻结的字节满足时 它的阶梯预算仍然可以通过
每张支票 分级器配置错误不同于普通失败
检查。 模型传言,时间戳,耐久,格式化从不决定等级.

在报告和仪表板中保持这些字段的分离. 充气协议
以任务成功完成 奖励有自信的停止
而不是用来生成正确的文件。

## 来自持久事件的计量

`aggregate_metrics()` 从保留会话中获得评价指标
运行中的事件而不是可变的计数器。 报告指出:

- 模型转换、工具调用、错误动作和工具错误;
- 生成后端报告时输入和输出符号;
- 重新使用、重用和新加的代币;
- 可见的工具结果字节和压缩计数;
- 可用时生成延迟、时钟评价时间和终端
  为什么?

只有脚本字符串生成器没有 token 或缓存测量,所以
字段仍然未知,而不是成为误导的零。 等级顺序和
状况不取决于业绩计量。

保留完整的会话跟踪来解释一个分数和比较
轨迹. 它可以包含提示,模型输出,源节录,工具
结果, diffs, 图像前, 和当地路径。 处理会议和评价
记录为敏感数据:不要仅仅因为汇总而公布。
衡量标准可以安全分享。

## 所剩时间已推迟

这个检查站确实有 **没有** 执行模式作者 Python,pytest,编译器,
建立系统、任务本地分级或显示命令。 临时
目录和 `cwd` 是路径选择的便利,而不是禁闭。 运行
在主机上的程序会给候选人代码 评估者的文件系统,
程序、证书和网络权威。

因此,一般行为编码评价需要后端加上一个
实际隔离边界,例如一次性容器或虚拟机器
仅读的基图像、 明确的可写挂载、 默认禁用的网络,
从外部提供的资源限制、流程清理和可信测试
候选工作空间。 只有后端应安装和运行被搁置的 pytest 或
尝试范围更广的顶点。

其他有用的扩展包括重复抽样运行,模型比较,
统计置信间隔,防漏的外部任务分布,
并持久地重新开始在建分级工作。 他们中的任何人,不改变日,
7规则:任务正确性来自一个独立、有决定力的分级员,
可执行候选人代码不得运行而不实际隔离.
