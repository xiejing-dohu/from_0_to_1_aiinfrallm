# 🚧 第 3 周可选扩展：推测解码

>           本任择章节正在审查之中,可能有所改动。

光谱解码使用一个较小的模型草案来提出几个符号,然后
要求目标模型在一个呼叫中验证它们。 减少接受的草稿令牌
目标模型的数目 decode 步骤而不改变目标
分发。

您解决方案中的检查点执行 **贪婪** 投机解码 :
草稿的代号被接受的同时它们与目标模型的贪婪代号匹配.
将同样的循环延伸至采样需要概率正确接受
和残余取样规则; token 平等是不够的。

## 目标

到本章结尾,你应该能够:

- 以较小的范本草案提出有限度的提案;
- 在一次目标模式呼叫中核实若干拟议职位;
- 接受匹配前缀并在第一次不匹配时恢复;
- 在不腐蚀抵消的情况下,倒转密集和呼号的缓存;
- 决定接受率是否抵消草稿和核查间接费用。

## 先决条件

- 完成草稿和目标模型的第二周缓存生成。
- 完成第3周的页面缓存和了解页面的注意路径。
- 两种模型使用兼容的标识器。 一个共享的 token 编号必须代表
  两种词汇中相同的文字。 在任何一种模式之前验证该合同
  运行; 不匹配的快捷编码、 EOS 代号或词汇必须关闭 。

由于两个具体原因,这一延期是在引起注意之后进行的。 被拒绝
草稿令牌必须释放页面并修复有效的尾端长度, 并验证
数个提议牌子一时是长时的注意,
前缀。 因此,页卡片生命周期和页卡片长清水操作符
构成用于构建投机解码的稳定接口。

## 任务 1: 让缓存倒转合同

添加 `rewind(n)` 转到常用的 KV 缓存接口。 密密的缓存删除最后的
`n` 逻辑位置。 页面缓存还必须返回未使用的页面
并缩短新尾页的有效前缀。

校验零长倒带, 一页内倒带, 一页间倒带
边框,并完全倒转:

```bash
pdm run test --week 3 --day 3 -- -k rewind
```

## 任务2:制作一个有界限的草稿

选择一个小建议长度, 如 4 。 从最后接受开始
token,运行模式一草案 token 并保留提议的
页:1 早点到EOS站

保持建议长度的可塑性。 更长的建议会减少目标呼叫
只有在接受率仍然很高,足以偿还额外工作草案时才能接受。
使用默认的 4 , 并将 0 当作一个明确的只设定目标的回落 :

```python
speculative_generate(
    draft_model,
    model,
    draft_tokenizer,
    tokenizer,
    prompt,
    proposal_length=4,
)
```

## 任务3:在一个目标呼叫中验证

递过去最后接受的 token 随后是目标模式的提案草案。
一个电话。 请求每个位置的对数, 然后比较目标
与对齐的草稿序列的贪婪符号.

及时提出建议和核查 token 支持的32位数中的数组
整数 dtype. 未签名并签名的混合 32 位 token 数组可以促进 a
压缩到64位指数,将嵌入式表示拒绝.

第一次供应 token 已被接受。 从下一个位置开始,
找到最长的匹配前缀 。 如果每个草稿 token 匹配, 保留目标
下一个模型 token 因此,世代可以在没有额外目标呼叫的情况下继续.

## 任务 4: 提交或倒转

将缓存抵消视为正确性不变量 :

- 在完全接受后,通过被接受的提议推进两个缓存;
  将草稿缓存与目标的额外同步 token;
- 在不匹配,发射目标 token 在那个位置,然后每晚倒回
  两种缓存的投机位置;
- 在任何一条路径之后,坚持草案抵消、目标抵消和逻辑
  每层缓存的长度一致。

第一、中和最后提议的锻炼不匹配 token测试 a
完全被接受的建议 和EOS在一个建议。 比较完整的输出
与普通贪婪的一代 从目标模型。

```bash
pdm run test --week 3 --day 7
```

以小型草稿模式和更大的目标模式运行集成路径:

```bash
pdm run main --solution tiny_llm_ref --loader week3 \
  --draft-model qwen3-0.6b --model qwen3-4b
```
