## 一个合作取消信号

`CancellationToken` 是一个线性安全 第一写手的信号 第一个电话
改为 `cancel(reason)` 修正原因; 后调用者无法替换它 。 传过去
不变 token 通过循环、生成会话和工作空间:

```python
cancellation = CancellationToken()
workspace = Workspace(
    policy,
    session_log=session,
    cancellation=cancellation,
)
generation = GenerationSession(
    model,
    tokenizer,
    cache_factory,
    max_tokens=512,
    cancellation=cancellation,
)
result = run_agent(
    task,
    generation,
    workspace,
    session=session,
    cancellation=cancellation,
)
```

执行工作注意到明确安全边界的信号:

- 在准备或发出示范请求之前;
- 在课程模型中产生的符号之间 decode 循环;
- 在发出工具之前;
- 在文件意图持久但原子替换之前;
- 而投票是允许的命令。

取消加薪 `AgentInterrupted` 稳定的原因和阶段
观察它。 `run_agent()` 附加一个 `interrupted` 事件之后,
未完成 `run_finished` 活动。 部分高级生成缓存是
被抛弃而不是再利用。 CLI 报告已知的文件和命令侧面
对于中断运行,效果和退出状态为130。

如果一个通用后端在取消前完成完整响应
观察到,用于缓存/审计一致性的循环记录,然后
附加一个明显的错误观察, 说明它没有动作
执行。 因此,复会不能错失丢弃的行动
对于应该重播的工作。

取消是合作性的,而不是先发制人。 一个 MLX 内核已执行
设备必须在此之前返回 Python 可以观察 token无国籍人
`--solution mlx` 兼容性后端没有每盘路由循环,因此可能
并只在Ctrl-C的后端产生控制时进行观察。

## 替换文件前的日志

当a `Workspace` 拥有匹配的会话日志, 每个被批准 `write_file` 或
`edit_file` 记录边框 `mutation_intent` 在原子取代之前。 那个
意图包含已规范的路径、 文件前图像和模式
已存在, 预定的后写模式, 以及前面和后面的 SHA-256 散列
意图在字节之后。 日志在工作空间前被冲洗并同步
被感动。 页:1 `mutation_committed` 事件只跟随当前
文件散列和模式匹配意图。

最后的写法是从一个开放的,身份检查的工作空间根文件
释义者. 每个家长都打开了 `O_NOFOLLOW`; 目标重新验证
相对于一个持有的父母描述符。 安装是不可替换的。 对于一个
已存在文件, 执行先将当前名称移动到私密处
备份, 验证该精确条目, 仅在目的地安装新文件
仍然缺失,并在成功或失败后保留备份。 页:1
在重命名之前打开旧inode的作家
hold 的描述符, 因此删除备份将有可能删除已写入的字节
同时 这些保护 `.tiny-llm-agent-*.bak` 文件被保留
手动检查和表面 `AgentRun.retained_recovery_files`
和CLI副作用总结. B. 实施情况
工作空间外的父目录互换。 报告是保守的:a
在备份重命名在 tuple 中留下保留路径之前中断
尚不存在; 已报告的每个路径都需要手动
检查。

这些检查保护了核定目标及其目录的行距正常
同时编辑。 它们不是另一个进程的安全边界
以同一用户运行,该用户有意发现和比对随机
`.tiny-llm-agent-*` 或 `.tiny-llm-undo-*` 内部名称。 便携式 POSIX 软件 Python
不提供无链接的操作。
在解除连接前立即进行内部输入,并在
身份检查失败了 在另一个时使用容器或虚拟机
共享账户的程序不可信。

如果进程在这两次事件之间停止,则构建工作空间或
电话 `recover_pending()` 分类当前内容和模式指纹 :

| 当前文件状态 | 回收分类 |
| --- | --- |
| 预定在散列和模式之后 | `committed` |
| 在散列和模式前录制,包括仍然丢失的新文件 | `not_applied` |
| 其它散列或模式、不安全类型或不可读目标 | `conflict` |

回收只附加分类。 它从不写、删除或恢复
一个文件。 CLI报告启动时发现的冲突. 这种区分在下列地点很重要:
原子替换边界:在替换后,取消可能到达。
完成,但在承诺事件持续之前。 指纹核对
记录完成的替换,而不是重放或猜测。 仅限字符
更改与记录的指纹不符,因此是冲突。

图像前缀为UTF-8文本,会话记录很敏感.
崩溃后的恢复只有在持续的时间里才能持久; `--no-session` 保留
在内存中的日记,在进程退出后无法恢复。

## 检查点和默认- 无撤消

`MutationJournal.create_checkpoint(name)` 记录分支- 本地事件边界
在解决待决意图之后。 `plan_undo(checkpoint)` 永不改变工作空间
字节:它首先记录任何未决意图、崩溃的分类
已执行的检查点后突变为每条路径恢复一次,预计最新
准确的内容和模式指纹,并带有命令活动的警告
文件日记不能反转。

撤销仍然是单独的、明显的副作用:

```python
assert workspace.journal is not None
checkpoint = workspace.journal.create_checkpoint("before parser edit")

# ... approved write_file or edit_file calls ...

plan = workspace.journal.plan_undo(checkpoint)

def confirm_undo(_plan):
    try:
        answer = input("Apply this undo plan? y/N ").strip().lower()
    except (EOFError, KeyboardInterrupt):
        return False
    return answer in {"y", "yes"}

result = workspace.journal.apply_undo(plan, confirm=confirm_undo)
```

闪烁 `confirm` 拒绝取消。 空响应, EOF, 中断, 或
除了一个明确 `y` 或 `yes` 也必须否认。
在提示之前, 执行会预先飞行整个计划; 任何内容
或模式冲突,包括 chmod- only更改,每个文件保持不变。
它恢复现有文件的原始内容和模式并删除文件
是经纪人创造的

每条路径在恢复或拆除之前都要再次检查。 又一个
整个计划预飞后, 进程仍然可以比赛: 较早的路径可能已经
在以后报告冲突之前恢复。 长久不变的事件
`UndoResult` 诚实地报告部分结果。 没有重做操作
这个检查站。 每次恢复/清除都有自己的写头更改ID和
预期结果内容和模式指纹,以及确切名称
其覆盖的突变特异性ID. 崩溃后, 重试调节开始的更改
在它问及是否继续之前,是否适用;
永远不要重放已经应用的更改或将后期突变作为其中的一部分
先前审查的计划。

撤销使用相同的根- 安氏目录 traversal. 删除第一个重命名
检验其字节和模式
在使原始路径不存在之前。 恢复隔离并核实
当前条目,然后使用无替换安装。 公共目标检疫或
每次成功操作后保留备份,因为另一个进程可能
仍然持有一个可书写 描述该inode。 它的精确保护路径是
选择并在突变前进行日记,然后返回
`UndoResult.retained_recovery_files`,包括在崩溃调节后。 若为
另一个演员替换文件,操作报告冲突并恢复
或保存隔离字节,而不是删除或覆盖
替换。 保守地说 包括每个开始的 行动的保留
因此,如果中断发生在
检疫重命名;每个确实存在的条目都需要人工检查. 那个
代理创建和初始验证的内容被限制,但 a
持有旧描述符的作家可以不断生长一个保留inode. 重复
因此,复制件可以消耗磁盘;操作员可以检查并删除所命名的磁盘。
`.tiny-llm-undo-*` 稍后的证据。

命令不是文件变异 。 检查点后的命令增加了警告
但它的文件系统、网络、进程或其他主机效果没有跟踪,
无法由 `MutationJournal`中记录了持久的命令ID
发射前再次检查取消 `Popen`,正常完成为
链接 `command_finished`。重启时,处理任何未匹配的发射记录
既是副作用,又是清理的不确定因素。

## 分支对话,而不是工作空间

`SessionStore.branch(parent_session_id, at_event_id)` 在 a 创建新会话
关闭祖先边界。 新会话记录主会话和活动,
复制重建所需的语义用户、助手、工具和运行事件
上下文,保留用于审计的源事件ID,并结束构造
持久 `branch_completed` 标记。 中断的部分分支被拒绝
被最新的会议选择忽略了 一个没有匹配工具的家长,
突变、取消更改或命令——或记录的恢复冲突——不可能
分支直到其共享工作空间状态得到解决。 分行不会改变
父母的JSONL文件。

这些行动仍然刻意分开:

- **压缩** 将永久历史转换成模型。
- **会话分支** 在一个祖先开始一个新的对话序列。
- **工作空间撤销** 冲突检查并恢复日记文件突变。

分拆从不恢复文件, 并取消从不删除先前的记录
尝试。 如果新建对话分支, 则明确选择并应用撤消计划
还需要较长的工作空间字节。

## 引导、分支和现场缓存

引导、收缩和分支都能够改变旧部分
使迅速。 他们使用第4天缓存规则: `GenerationSession`
标记新信件, 查找 token 时间最长的常用前缀
缓存,将每一层倒回到那个边界,并预填新后缀. 若为
层偏移不统一或倒转失败,会掉下所有层并开始冷。

分支和检查站活动不存储 K/V 的借数或承诺缓存
token 长度。 一个重启的过程总是从语义事件重建.
持续的K/V快照和分支特定缓存登记册被推迟。

## 命令和回收边界

一个允许的命令在没有 shell 和一个新的进程组中启动 。 与
注销 token投票时间间隔,并试图
在取消或超时时杀死和收获那群人。 这是清理,不是
隔离:儿童可以创建另一个会话,核准的可执行文件可以访问
工作目录以外的路径,以及停止前发生的效果
保持真实。 使用一次性工作空间,即使每次通话都有 `y/N`
е翴

第6天检查站故意推迟:

- 集装箱或虚拟机器隔离;
- 并行的TTY导线;
- 持续的K/V缓存快照;
- 重做和交易性原子多文件撤销;
- 暂停评价和正确评级。

`AgentRun.completed` 仍然意味着模型产生了有效的最终行动.
这并不意味着任务是正确的或者验证命令已经通过。
